# sp_DataProfile v0.4 — July 2026

The first release in over eight years. v0.4 is a major performance overhaul: the expensive
per-column, scan-per-metric profiling in Modes 1 and 2 has been rewritten to run in a fixed,
small number of table scans. It also adds fast row-counting and approximate-distinct options,
switches the project to the MIT License, and ships full documentation.

> ⚠️ **Breaking change:** the minimum supported SQL Server version is now **2012** (was 2005).
> The single-pass `CROSS APPLY (VALUES ...)` reshape used by the Mode 1 and Mode 2 rewrites
> requires SQL Server 2012, so the proc now hard-errors on older versions (`@SQLMajorVersion < 11`).

## Performance

- **Mode 1 (Column Detail) — single-pass rewrite.** The three per-metric cursors
  (unique / null / min–max length) are replaced by one code-gen cursor that builds a single
  wide aggregate `SELECT ... INTO #agg` — the only base-table scan — then reshapes the 1-row
  result into the profile table via `UPDATE ... CROSS APPLY (VALUES ...)`. On a wide table this
  collapses 100+ scans into **one**.
- **Mode 2 (Column Statistics) — single-pass rewrite.** The per-column stats cursor
  (~2 base-table scans per numeric column) is replaced by two dynamic batches: one wide
  aggregate scan for min/max/mean/std_dev, and one `PERCENTILE_DISC` scan for medians (window
  functions can't share the scalar-aggregate scan). Mode 2 now costs **2 scans total** instead
  of ~2 per numeric column. All output columns and values are preserved (int `AVG` widened to
  `bigint`, `STDEV` → `NUMERIC(18,4)`, median still gated on compatibility level 110+).
- **Instant row counts by default.** Row count now reads from `sys.dm_db_partition_stats`
  (near-instant, no scan), falling back to `COUNT_BIG(*)` when sampling or when `@ExactRowCount = 1`.
- Min and max string length are computed in a single scan instead of one each; `COUNT(DISTINCT)`
  is skipped on `nvarchar/varchar/varbinary(max)` LOB columns.

## New parameters

- **`@ExactRowCount BIT = 0`** — force an exact `COUNT_BIG(*)` instead of the fast
  metadata-based count.
- **`@ApproxDistinct BIT = 0`** — use `APPROX_COUNT_DISTINCT` on SQL Server 2019+ (falls back
  to `COUNT(DISTINCT)` on older versions) for distinct/unique counts in Modes 1 and 4.

## Behavior changes

- **Mode 1 now honors `@ColumnList`** — profiles only the requested columns instead of every column.
- The final Mode 0 select also now honors `@ColumnList`.

## Compatibility

- **Minimum version raised to SQL Server 2012** (`@SQLMajorVersion < 11` hard-errors). The
  single-pass `CROSS APPLY (VALUES ...)` reshape requires 2012.
- Median (Mode 2) still degrades gracefully, skipping with a warning on databases below
  compatibility level 110.

## Correctness & hardening

- `QUOTENAME` applied to the median `ORDER BY` column and the Mode 3 catalog-view queries;
  fixed cross-database schema resolution in the column-type lookup.
- Dynamic SQL variables widened from `NVARCHAR(4000)` to `NVARCHAR(MAX)`.
- Unique-values cursor now properly closed/deallocated; dead `@DatabaseID` declaration removed.

## Licensing & docs

- **Now MIT-licensed** (added `LICENSE`); the old EULA/jorriss.com links in the README and proc
  header are replaced with the GitHub source and MIT reference.
- Added an in-file header comment block with version, mode reference, and usage examples.
- Overhauled README (badges, quickstart, sample output tables for Modes 0–2, TOC, contributing)

## Upgrading

Reinstall by opening [sp_DataProfile.sql](../../sp_DataProfile.sql) in SSMS and executing it
against your instance — it `DROP`s and re-`CREATE`s `dbo.sp_DataProfile` in `master`. No other
steps. Confirm the target instance is SQL Server 2012 or newer.
